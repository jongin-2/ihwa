## ② 기능 차이(한 앱만 가진 검사) — 초안은 모두 합침
| 검사 | 있는 앱 | 없는 앱 |
|---|---|---|
| 케이스 0건이면 실패(번호 형식 불일치 헛통과 방지) | 응원석 | 나머지 3 |
| 결과 칸에 판정(통과·실패·실행 불가·폐기·고침·보류) 없으면 실패 | 차곡(+ 전체 회귀 절 판정까지) | 나머지 3 |
| 번호 묶음 풀기 `A-01·02`, `DEP-02~06`, `SCAN-04/05` | 차곡 | 나머지 3(첫 칸에서 번호만 모두 찾음) |
| SOLVABLE(이미 방법이 있는 사유) 차단 | 주량체커·응원석·알롱 | 차곡 |
| 전체 회귀 절 존재 시 거기에 모든 케이스, 없으면 출시 회귀 절 + 승계 줄 | 주량체커·알롱 | 응원석(버전 하드코딩), 차곡(전체만) |
| 옛 "<버전> 전체 회귀" 절도 받음 | 주량체커·알롱 | 응원석(1.0.0 외엔 거부) |
| 문제를 모아 한 번에 출력 | 차곡 | 나머지는 ✗ 줄 즉시 출력(결과 같음) |
| 저장소 외 도우미 모듈 필요 | 주량체커(store/shots_dir) · 차곡·알롱(work_paths) | 응원석 |

## ③ 버그·뒤처짐
| 항목 | 상태 | 내용 |
|---|---|---|
| 응원석 출시 회귀 느슨함 | 뒤처짐 | 1.0.0 아닌 버전은 "절 안에 케이스 번호 아무 데나 + '승계'라는 낱말"만 있으면 통과. 주량체커·알롱은 `| ID` 표 행 1건 이상 + `> 승계: 나머지는 <버전> 결과` 줄 필요. 초안은 엄격 쪽 → 응원석 1.0.1·1.1.0 절은 승계 줄만 추가하면 통과(결과 §cheerseat) |
| 응원석 첫 출시 판별 `!= '1.0.0'` | 뒤처짐 | `1.0` 형식이면 출시 회귀 쪽으로 가고, "전체 회귀" 절을 선택하는 일반 규칙이 없음. 새 앱 복사 때 버전 문자열이 하드코딩된 채 퍼질 위험 |
| 응원석 ROOT 고정 | 뒤처짐 | `parent.parent.parent` — 스크립트 위치가 바뀌면 깨짐(주량체커·알롱은 `.git`까지 탐색) |
| 응원석 작업 기록 | 뒤처짐 | 아직 옛 `impl/qa/`(iCloud work/ 폴더가 없음) — 규칙 2절의 이전 대상 |
| 주량체커·응원석·알롱 판정 빈틈 | 뒤처짐(차곡이 고침) | 마지막 결과 행 둘째 칸이 "실기기 대기" 같은 판정어 밖이면 그 행을 건너뛰고 더 앞의 행(예: 통과)을 현재 상태로 삼는다. 실제로 주량체커 ACC-36(`실기기 대기`)이 이 때문에 검사에 안 보임 → 초안은 "실기기 대기"도 시도 기록 필요 상태로 취급 |
| 차곡 SOLVABLE 없음 | 뒤처짐 | "새로 설치 불가"·"시간 배분" 같은 사유로 실행 불가를 적어도 안 막힘 |
| 차곡 `--release` 형식 | 의도 | "빌드 N 전체 회귀"(출시 회귀 절 모드 없음). 초안은 설정으로 유지 |
| 응원석 머리말 | 사소 | 설명이 "impl/qa/QA_RESULT.md"로 옛 위치 가정, 주량체커 scripts/ 경로를 가리킴 |
| 4개 공통 | 사소 | 전체 회귀 절 판정 열 검사는 차곡만. 초안은 전체 절의 판정 확인을 모두에 적용(뒤 행이 판정을 덮지 않게 보정) |
| 전역 규칙 문구 | 확인 필요 | "끝자리가 0이 아니면 전체 버전 절 요구"는 현재 코드(1.0만 전체, 이후 출시 회귀 + 승계)와 어긋나 보임 — 코드 동작을 따랐음. 종인님/코어가 문구 확인 |
