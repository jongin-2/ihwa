# ihwa — 공개 개인정보처리방침·이용약관

> 고객 지원 페이지는 2026-10-10 주량체커 1.2.0 출시와 함께 내렸다(앱 안 지원 메뉴 삭제 #149, 스토어 지원 URL은 방침 주소). 문의는 방침·약관 본문의 이메일로 받는다(심사 1.5).

주량체커(DrinkChecker)·차곡(Chagok) 두 앱이 함께 쓰는 **공개 페이지**다. **약관·방침·지원의 원문은 여기뿐이다** — 앱은 본문을 들고 있지 않고 아래 언어별 주소를 주소가 보이지 않는 앱 안 웹뷰로 연다(Safari 시트는 도메인이 드러나 쓰지 않는다)(2026-09-28 종인님 규칙: 앱 출시 없이 고칠 수 있게). App Store Support URL·방침 URL도 이 주소다.

- 개인정보처리방침: https://jongin-2.github.io/ihwa/privacy/
- 이용약관: https://jongin-2.github.io/ihwa/terms/
- 앱 안에서 여는 언어별 주소: `…/<privacy|terms>/ko/`, `…/en/`(build.py가 `## 한국어`·`## English` 절을 떼어 만든다)

## 방침·약관을 고칠 때 — 이전 판을 반드시 남긴다(2026-10-10 종인님)
1. 고치기 **전에** 지금 `src/<privacy|terms>.md`를 `src/archive/<privacy|terms>/<그 판이 게시된 날짜>.md`로 그대로 복사한다(아래 규칙 — 최종 수정일과 같아야 정상).
2. `src/…md`를 고치고 최종 수정일을 바꾼다.
3. `python3 build.py` → 커밋·푸시. 제목 바로 아래에 버전 고르기(날짜 드롭다운 — 현재 판은 `최종 수정일` 날짜 + (현재), 아래로 보관 판 날짜. 10-12 종인님 "보통 드롭다운 리스트박스 같은 형태", 토스·쿠팡 사례)가, 보관 판(`/<문서>/archive/<날짜>/`, `/ko/`·`/en/`) 위에는 "이 문서는 <날짜> 판입니다 · 현재 버전 보기"가 자동으로 붙는다.
- **본문을 한 글자라도 고치면 최종 수정일도 그날로 바꾼다** — 10-06·10-07에 최종 수정일을 09-28로 둔 채 고쳐, 보관 때 10-07 내용이 '09-28 판'으로 잘못 남았다(10-10 응원석 세션이 git 기록으로 바로잡음: 날마다 마지막 게시 판을 **게시된 날짜** 이름으로 보관 — 방침 09-27·09-28·10-06·10-07·10-10, 약관 09-28·10-06·10-07).
- 보관 이름은 그 판이 **게시된 날짜**(같은 날 여러 번 고쳤으면 그날 마지막 판). 종인님 10-10 "약관들은 이전 버전 모두 확인 가능해야 하는 거 잊지 마".
- 보관 판은 지우거나 고치지 않는다(당시 사용자에게 보인 문서 그대로). 주량체커 방침 첫 보관: 2026-09-28 판(10-10 계정 연결 개정 직전).

원문은 `src/*.md`, `python3 build.py`로 `docs/`를 만든다(GitHub Pages가 `docs/`를 게시). 고치면 `python3 build.py` 후 커밋·푸시만 하면 두 앱에 바로 반영된다(Notion 사본은 폐기).

## 앱 안 약관 화면 — 세 앱 공용 원본(2026-10-12)
종인님 "약관 같은 건 모든 앱 화면도 동일하게 구성하고 잘 관리하면 될 것 같은데 왜 자꾸 달라지지" — 앱마다 따로 짠 사본이 고칠 때마다 벌어졌다(주량체커·응원석 가운데 제목, 차곡 큰 제목 + 원 ✕).
- 원본: `app-kit/LegalDocView.tsx` 하나. 머리글(가운데 제목 · 오른쪽 30pt 회색 원 ✕ · 넘어간 문서에서만 왼쪽 원 ‹ — iOS 시트 표준 닫기 단추)까지 이 부품이 그린다 — 이동 방식(react-navigation·expo-router)과 무관. 기준은 응원석 세션이 잡고 다른 앱이 따른다(종인님 "주량체커 따를 필요 없고 좋은 걸로 너가 기준 잡고 주량체커가 따르게 해").
- 각 앱은 이 파일을 **글자 그대로** `src/components/LegalDocView.tsx`(차곡은 앱 구조에 맞는 자리)에 복사하고, 모달 시트로 띄우되 네이티브 머리글은 숨긴다. 앱마다 다른 값은 강조색(tint) 하나.
- 고칠 땐 원본만 고치고 세 앱에 다시 복사. 각 앱 빌드 점검(check-docs-sync)이 원본과 다르면 막는다.
- 필요한 라이브러리: react-native-webview, expo-clipboard.

## 앱 업데이트 안내 — 모든 앱 공용(2026-10-14)
종인님 "업데이트 유도 방식은 모든 앱 동일하게 하고, 앱에 따라 업데이트 미룰 수 있는 것과 무조건일 수는 있어".
- 원본: `app-kit/UpdatePrompt.ts` — 각 앱은 글자 그대로 복사해 쓴다(라이브러리 없음). 앱을 열 때마다(처음 실행·백그라운드에서 돌아올 때) App Store 공개 조회로 최신 버전을 보고, 새것이 있으면 iOS 경고 창 `새 버전이 있어요` / `버전 {v}` · `나중에` · `지금 업데이트`. '나중에'를 눌러도 다음에 열면 다시 뜬다(종인님 결정). 설정 버전 줄의 `업데이트` 단추는 `useUpdateState()`.
- **무조건 업데이트**: `docs/app-config/<앱>.json`의 `minVersion`을 올리고 커밋·푸시하면, 그보다 낮은 버전은 `나중에` 없이 `지금 업데이트`만 보인다(앱 출시 없이). 기본은 각 앱의 첫 출시 버전(= 끔). 파일 이름: 주량체커 `drinkchecker`(QA앱은 시험용 `drinkchecker-qa` — 운영 사용자에게 번지지 않게), 응원석 `cheerseat`, 차곡 `chagok`(각 앱이 쓰기 시작할 때 만든다).
- `docs/`는 build.py가 만든 페이지와 함께 이 폴더도 그대로 게시한다(build.py는 `app-config/`를 건드리지 않는다).
